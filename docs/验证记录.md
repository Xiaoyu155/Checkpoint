### 首次失败暴露的问题

1. 缺少 `.agent-workspace` 时，`mission start --test-command ...` 仍因 missing workspace 在 planning 阶段阻断。
   - 修复：`run_chief_mission` 在提供 `--test-command` 且 workspace 不存在时自动 `init_workspace(..., with_demo=False)`。

## 2026-07-04 Phase 1 / V2：用 DevPacer 给 DevPacer 开发功能

### 目标项目

### 暴露并修复的问题

1. workspace 初始化写入的 `.gitignore` 会导致目标仓库变脏并阻断真实 dispatch。
   - 修复：dirty gate 允许只包含 Checkpoint 运行时 ignore 行的 `.gitignore` 变更通过，用户自己的 `.gitignore` 改动仍会阻断。

2. 强制测试记录 `强制测试记录.md` 由产品写在 repo 根目录，下一轮 mission 会把它当成用户脏文件。
   - 修复：dirty gate 和 workspace runtime 前缀都忽略该强制记录；`git status` 使用 `core.quotePath=false`，避免中文文件名被八进制转义。

3. 曾出现假阳性：worker 未真正创建/执行，0 workflow dry-run 验证仍把 mission 标成 `verified`。
   - 修复：只有 worker record 为 `completed` 时，验证 `pass` 才能提升为 `verified`；worker 失败时即使命令门禁 pass 也只能是 `worker_failed`。

4. Codex worker prompt 直接放在 argv 中，repo map 较大时 Windows 报 `The command line is too long.`。
   - 修复：Codex worker 使用 `codex exec ... -`，通过 stdin 传递长 prompt；预览命令显示为 `< prompt via stdin>`。

5. 计划阶段的 changed files 会被 Checkpoint 自身产物污染。
   - 修复：`chief_engineer` 过滤 `.agent-workspace/`、`.visual-agent-status.md`、`强制测试记录.md` 和生成型 `.gitignore`；`git_diff` 统一使用 `core.quotePath=false`。
