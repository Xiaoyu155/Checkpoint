# Public Launch Checklist

Use this checklist before asking external developers to try Checkpoint.

## Required Green Gates

Run from a clean checkout:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\bootstrap.ps1 -Step all
powershell -ExecutionPolicy Bypass -File scripts\release_candidate.ps1
```

Expected:

- `doctor` reports `perception.dom_browser: true`.
- `doctor.playwright.ready` is `true`.
- `verify-now --live` reaches `L4` and `Strict product acceptance (L3+ without blockers): 1/1` on `checkout_verification`.
- The public demo completes the green -> red -> green loop.
- No public README or marketplace text uses the old pre-Checkpoint command label.

## GitHub Repository Metadata

Set these in the GitHub repository settings:

- Description: `Local-first acceptance checks for AI coding assistants, with MCP tools, Playwright workflows, safety profiles, and audit trails.`
- Homepage: `https://github.com/Xiaoyu155/Checkpoint/blob/main/docs/quickstart.md`
- Topics: `mcp`, `ai-agents`, `coding-agents`, `playwright`, `acceptance-testing`, `workflow-automation`, `local-first`, `vscode-extension`, `qa-automation`, `developer-tools`

## GitHub Release

Publish a new preview release after the green gates pass.

Suggested title:

```text
Checkpoint v0.1.1-preview: Local Acceptance Checks for AI Coding Agents
```

Attach:

- Source archive generated by GitHub.
- VS Code `.vsix` package when available.
- A short demo GIF or MP4 showing: break UI copy, run Checkpoint, inspect structured failure, fix, rerun green.

## PyPI

The public Python package name is still `visual-agent`; the CLI command users should run is `checkpoint`.

Build locally:

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade build twine
.\.venv\Scripts\python.exe -m build
.\.venv\Scripts\python.exe -m twine check dist\*
```

Smoke-test the built wheel in a clean virtual environment before upload:

```powershell
python -m venv .venv-publish-smoke
.\.venv-publish-smoke\Scripts\python.exe -m pip install dist\visual_agent-*.whl
.\.venv-publish-smoke\Scripts\checkpoint.exe --version
.\.venv-publish-smoke\Scripts\python.exe -m playwright install chromium
.\.venv-publish-smoke\Scripts\checkpoint.exe doctor
```

Upload only after the smoke pass:

```powershell
.\.venv\Scripts\python.exe -m twine upload dist\*
```

## VS Code

Prepare screenshots listed in `vscode-extension/PUBLISH_CHECKLIST.md`, then:

```powershell
cd vscode-extension
npm ci
npm test
npm run package
```

Install the `.vsix` into a clean VS Code profile and run:

- `Checkpoint: Init Workspace`
- `Checkpoint: Verify Now`
- `Checkpoint: Show Product Issues`
- `Checkpoint: Show Latest Failure`

Publish after the clean-profile smoke pass.

## First Outreach

Do not optimize for stars first. Ask 10 developers to try one task:

```text
Clone Checkpoint, run the 60-second start, break the checkout button copy, and confirm Checkpoint reports the exact failed assertion.
```

Track:

- Did bootstrap finish without manual environment edits?
- Did the first live verification pass?
- Did the failure message tell them what to fix?
- Did they understand how Checkpoint differs from Playwright alone?

If 10 direct users are not available, use `docs/first_user_feedback_plan.md#if-you-cannot-recruit-10-users-yet` and collect asynchronous install/demo feedback first.
Keep the `60-second demo feedback` issue template enabled so strangers can report setup results without a scheduled call.
