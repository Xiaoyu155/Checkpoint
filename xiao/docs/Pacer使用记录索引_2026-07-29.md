## 为什么之前会觉得“最新记录消失”

主要原因不是完全没有记录，而是记录分散：

1. `xiao\.agent-workspace\missions` 最新 mission 停在 2026-07-12，会误导人以为后面没用 Pacer。
2. 2026-07-29 的开发 dogfood 在 `pacer-five-core-lab\.agent-workspace`，不在主仓 mission 目录。
3. 2026-07-29 的大量验证记录在 `run_history.jsonl`，不是 mission。
4. 记忆调用高频记录在 `gui/actions.jsonl`，不是 final report。
5. `.agent-workspace` 没有统一跨项目索引，所以“最近做了什么”需要跨 workspace 汇总。

## 产品缺口

Pacer 现在的问题不是完全没记录，而是记录没有被产品化地汇总成用户能看的“近期开发时间线”。

应该补一个命令：

```powershell
pacer usage timeline --days 14
```

输出应合并：

- missions
- journey
- run_history
- gui/actions
- host/session
- background records
- worktree evidence

并按真实时间排序，避免用户以为“下午开发记忆完全消失”。

## 下一步建议

1. 实现 `pacer usage timeline`，跨项目扫描 `.agent-workspace`。
2. 给每条 mission/run/action 建统一 event schema。
3. 把 `mcp:get_pacer_memory` 的高频调用从噪声压缩成“记忆加载摘要”。
4. 在 final report 里自动引用最近 mission journey 和 run history，而不是只看当前 workspace。
5. 对“没有用户消息”事件做 intake 过滤，避免空事件打断同一条开发时间线。
