# Pacer 使用文档

> **Pacer** 是一个本地优先的 Codex 开发控制层。你用开发计划定义路线，Pacer 为 Codex 提供本地记忆、订阅/中转 provider 路由、托管执行和强测试验收。

## 1. 安装

**系统要求：** Python 3.11+，Windows 10/11

```bash
# 克隆仓库
git clone <repo_url>
cd <repo>

# 安装 xiao（从 xiao/ 子目录）
pip install -e xiao/

# 验证安装
checkpoint --help
```

安装后 `checkpoint` 命令即可全局使用。

---

## 2. 前提：AI 编码工具

Pacer 本身不包含 AI，它调度你已有的 AI 工具。至少需要安装以下一种：

| AI 工具 | 安装命令 | 验证 |
|--------|----------|------|
| **OpenAI Codex CLI** | `npm install -g @openai/codex` | `codex --version` |
| **Claude Code CLI** | `npm install -g @anthropic-ai/claude-code` | `claude --version` |
| **Gemini CLI** | `npm install -g @google/gemini-cli` | `gemini --version` |

### 只要你的电脑能用 codex，Pacer 就能直接用

Pacer 调用的是你系统上已安装的 AI CLI 工具（codex / claude / gemini），**共用同一个账号和额度**，无需额外配置 API Key。

- 如果你已经在 CMD、PowerShell 或 VSCode 终端里用过 `codex` 命令，Pacer 可以直接用它
- 如果你用 `ccswitch` 切换 Claude Code 账号，Pacer 也跟着切换（因为调用的是同一个 `claude` 命令）
- 如果你有 OpenAI Codex 订阅，Pacer 用的就是该订阅额度

验证 AI 工具是否被 Pacer 识别：

```bash
checkpoint agents doctor
```

## 3. 快速上手（5 分钟）

```bash
# 进入你的项目目录，启动一次 Pacer Agent
cd D:\myproject
pacer
```

随后直接持续输入自然语言任务。Pacer 默认使用用户已安装的 Codex CLI、当前目录、delegated 托管、本地记忆、强验收和验证后合并。Codex CLI 可以使用用户订阅，也可以使用用户配置的中转 provider；Pacer Agent 不自动切换到 MiMo。第一次任务会自动创建 `.agent-workspace/`。主分支有未提交改动时，Pacer 可以在隔离 worktree 验证，但会安全阻止自动合并。

会话中可用 `/provider subscription` 选择 Codex 登录订阅，或用 `/provider relay <provider-id>` 选择已在 Codex `config.toml` 配好的中转。`/provider inherit` 恢复沿用 Codex 当前配置，单独输入 `/provider` 可查看当前选择。Pacer 只传 provider ID，不读取或保存 API key。

需要看任务、证据和队列时再打开工作台：

```bash
checkpoint dashboard
```

在工作台左侧「新建任务」里：
1. **目标**：用自然语言描述要做什么（例：`修复 src/calc.py 的 add 函数让 pytest 通过`）
2. **验收命令**：填你的测试命令（例：`pytest -q`）；留空则自动探测
3. **项目根目录**：留空自动填入当前项目路径
4. **AI**：选择 codex / claude-code / gemini
5. 点「▶ 执行」

Pacer 会在隔离的 git 分支里让 AI 改代码，自动跑测试，通过后任务进入「待验收」列，点「✓ 合并」才真正合并到主分支。

## 4. Web 工作台详解

启动命令：`checkpoint dashboard`（默认端口 8787）

### 4.1 页头

| 控件 | 说明 |
|------|------|
| **Pacer 工作台** | 当前项目路径（可点击切换） |
| **切换项目** | 切换到其他项目的工作空间 |
| **💬 对话** | 打开多轮对话面板（与 AI 对话） |
| **Agent 状态** | 已安装的 AI 工具状态（绿=已安装） |
| **Worker 控制** | 启动/停止队列 Worker（批量任务自动处理） |

### 4.2 看板

任务在四列之间流动：

```
待办 → 执行中 → 待验收 → 已完成
```

- **待办**：已创建但 Worker 还未处理的任务
- **执行中**：AI 正在改代码
- **待验收**：AI 改完并通过测试，等待你点「✓ 合并」
- **已完成**：已合并或已标记完成

点任意任务卡片可打开**详情抽屉**，查看：
- 停止原因（中文说明 + 修复建议）
- 改动文件列表
- 执行轮次记录
- 实时日志（执行中时自动刷新）
- 最终报告

### 4.3 新建任务（侧边栏）

| 字段 | 说明 |
|------|------|
| **目标** | 自然语言描述，要说清楚：做什么 + 改哪里 + 怎么算完成 |
| **验收命令** | 测试命令，如 `pytest -q` / `npm test` / `cargo test`；留空自动探测 |
| **项目根目录** | 你的代码库根目录（默认自动填入） |
| **AI** | 选择调用哪个 AI：codex / claude-code / gemini |
| **自动合并** | 勾选后通过验收即自动合并，无需手动点合并 |
| **预览** | 不实际执行，只生成执行计划供查看 |
| **▶ 执行** | 正式派发任务给 AI |

### 4.4 统计面板（左侧边栏）

- **已验收**：累计通过验收的任务数
- **执行中**：当前运行中的任务数
- **队列**：等待 Worker 处理的条目数
- **Codex 效率指标**：显示实际 provider、模型、缓存和 token 使用

## 5. CLI 命令参考

```bash
# 基础
checkpoint --help                          # 所有命令
checkpoint agents doctor                   # 检查 AI 工具安装状态
checkpoint status                          # 当前项目验收状态

# 工作台
checkpoint dashboard                       # 启动 Web 工作台（默认 8787 端口）
checkpoint dashboard --port 9000          # 指定端口
checkpoint dashboard --no-open            # 不自动打开浏览器

# 任务
checkpoint run --goal "修复登录 bug"       # 命令行直接运行
checkpoint run --goal "..." --agent codex # 指定 AI
checkpoint run --goal "..." --max-rounds 8 # 最多尝试 8 轮

# 队列
checkpoint mission queue --goal "..."     # 加入队列
checkpoint mission worker --watch         # 启动队列 Worker（持续处理）
checkpoint mission list                   # 列出所有任务

# 诊断
checkpoint doctor                          # 全面健康检查
checkpoint verify-now                      # 立即运行验收
checkpoint workspace-dashboard            # 工作空间总览

# 使用记录与证据
pacer usage timeline --days 14            # 最近 14 天做过什么，跨所有本地项目
pacer usage timeline --format json        # 同上，机器可读
pacer journey                             # 最近一个任务的五支柱证据链
pacer journey <mission_id>                # 指定任务

# 隔离 worktree 回收
pacer worktrees                           # 列出隔离 worktree，标出可回收的
pacer worktrees --reap                    # 真正删除（有未提交改动的一律保留）
```

`usage timeline` 汇总每个 `.agent-workspace` 里的 mission journey，
不用再手工翻 `.agent-workspace` 找记录。闭环那一行的符号含义：
`✓` 通过、`!` 证据不完整、`✗` 阻塞、`·` 待确认、`-` 本次无需。

## 5.1 验收到底证明了什么

Pacer 跑完验收命令后，会**再把同一条命令在改动前的版本上跑一遍**，然后分三档告诉你：

| 档位 | 含义 | 什么时候出现 |
| --- | --- | --- |
| `verified` | 确实做到了你要的事 | 命令改动前失败、改动后通过 |
| `regression_clear` | 只证明没弄坏别的东西 | 命令改动前就已经通过 |
| `unverified` | 没有任何独立证据 | 压根没给验收命令 |

只有 `verified` 会被当作"目标达成"。这条规则的原因很直白：**一条改动前后都通过的命令，
对这次任务的判别力是零**——它不可能告诉你目标有没有做到。以前 Pacer 会把这种情况也报成
"验收通过"，那是假绿。

推论（都是正常现象，不是 bug）：

- **纯重构**任务拿不到 `verified`。重构本来就该保持测试不变，它只能保证没弄坏。
- **改文档**这类任务通常是 `unverified`。没有能自动判别的门，该你自己看一眼。
- 想拿到 `verified`，就给一条**改动前会失败**的命令（先写测试再实现是最自然的做法）。

基线探测会多花一次执行时间，结果按 `(base 提交, 命令)` 缓存。急着要结果可以用
`--no-base-probe` 跳过，但那样最高只能报 `regression_clear`。

## 6. 多项目切换

一个 Pacer 工作台可以管理多个项目，通过页头「切换项目」在项目间切换：

1. 点击页头「**切换项目**」按钮
2. 输入你的项目目录路径（例：`D:\anotherproject`）或 `.agent-workspace` 路径
3. 点「切换」

Pacer 会自动检测 `D:\anotherproject\.agent-workspace`，无需手动找子目录。

弹窗中也会列出自动发现的已知工作空间，直接点击选择。

## 7. 对话功能

点页头「💬 对话」打开多轮对话面板：

- 在底部输入框输入消息，按 **Ctrl+Enter** 或点「发送」
- 支持**多轮对话**：历史上下文自动包含在每次请求中
- 可在面板顶部切换使用哪个 AI（codex / claude-code / gemini）
- 「清除」按钮清空对话历史（刷新页面也会清空）

对话功能调用的是本地已安装的 AI CLI，无需额外配置。

## 8. 队列 Worker

批量处理多个任务，无需一直守着：

```bash
# 方式一：命令行添加到队列
checkpoint mission queue --goal "重构 auth.py" --test "pytest tests/test_auth.py"
checkpoint mission queue --goal "修复支付 bug" --test "pytest tests/test_payment.py"

# 方式二：从 Web 工作台添加（执行 → 自动入队）

# 启动 Worker（持续处理队列中的任务）
checkpoint mission worker --watch
```

也可以在 Web 工作台右上角点「启动 Worker」按钮。

Worker 处理任务时：
- 每次取队列中第一个任务
- AI 在隔离分支里改代码
- 验收通过后任务进入「待验收」等待合并
- 失败时记录停止原因，可在工作台一键重试

## 9. Codex 订阅与中转 provider

### 共用订阅额度

Pacer 调用的是本地安装的 AI CLI，**共用你已有的订阅**：

- **codex**：使用你的 OpenAI Codex 订阅（每周刷新额度）
- **claude-code**：使用你的 Claude Pro/Team 订阅（每 5 小时刷新）
- **gemini**：使用你的 Google One/Gemini Advanced 订阅

无需为 Pacer 单独购买或配置 API Key。

### ccswitch 用户

如果你用 `ccswitch` 切换多个 Claude Code 账号：

```bash
# 切换到目标账号
ccswitch use <account-name>

# 然后启动 Pacer，自动使用切换后的账号
checkpoint dashboard
```

Pacer Agent 始终使用 Codex CLI 执行编码。认证只能来自 Codex 订阅，或 Codex `config.toml` 中配置的 OpenAI/Codex-compatible 中转 provider。Pacer Agent 不配置其他模型后端作为隐式备用通道。

## 10. FAQ

**Q: 启动 dashboard 后页面显示空白或没有任务？**

A: 确认已在项目目录运行过 `checkpoint init`。工作台显示的是 `.agent-workspace/` 里的数据，如果该目录不存在就会显示空。

**Q: Agent 下拉框里看不到 codex？**

A: 运行 `checkpoint agents doctor` 查看检测结果。可能原因：
- `codex` 命令不在系统 PATH 中（Windows npm 全局目录有时不在 PATH 里）
- 在非交互式终端中 PATH 可能不完整——尝试重启 dashboard

**Q: 切换项目后仍然显示旧项目的任务？**

A: 确认输入了正确的目录路径（项目根目录或 `.agent-workspace` 目录均可）。切换成功后页头项目路径会更新。

**Q: 任务停止原因是「仓库有未提交的改动」？**

A: Pacer 需要在干净的 git 仓库里工作。先 `git commit` 或 `git stash` 提交/暂存所有改动，再重试。

**Q: 验收命令超时怎么办？**

A: 可以减小测试范围（如 `pytest tests/unit/ -q` 而不是跑全部测试），或在任务目标里说明只跑部分测试。

**Q: 能打包成 exe 给非技术用户用吗？**

A: 可以，使用 `scripts/build_exe.ps1`（需要 PyInstaller）。打包后的 `Pacer.exe` 无需安装 Python 即可运行。

**Q: Pacer 会把代码发送到云端吗？**

A: Pacer 本身完全本地运行。你的代码只通过你选择的 AI CLI（codex/claude/gemini）发送给对应的 AI 服务，与直接使用那些工具完全相同。
