# xiao 使用指南

xiao 是一个本地 AI 编码任务调度器，让你用自然语言向 Codex / Claude Code / Gemini 等 AI 编码工具派发任务，自动执行、验收、管理多个项目的进度。

---

## 一、xiao 是什么，适合谁用

xiao 的核心是：**你描述目标 → xiao 调度 AI 改代码 → 自动跑测试验收**。

适合：
- 已经在用 OpenAI Codex CLI、Claude Code CLI、Gemini CLI 的开发者
- 想同时管理多个 AI 编码任务（多项目、多队列）的用户
- 想用 Web 界面而不是命令行看任务进度的用户

不适合（尚未支持）：
- 没有本地 AI 编码工具的用户（xiao 是调度层，不内置 AI 能力）
- 期待一键 EXE 安装的非技术用户（目前需 Python 环境）

---

## 二、前提条件

### 2.1 必须安装一个 AI 编码工具

xiao 目前支持三种后端，至少需要一种：

| 工具 | 安装方式 | 验证 |
|------|---------|------|
| **OpenAI Codex CLI** | `npm install -g @openai/codex` | `codex --version` |
| **Claude Code CLI** | `npm install -g @anthropic-ai/claude-code` | `claude --version` |
| **Gemini CLI** | `npm install -g @google/gemini-cli` | `gemini --version` |

**关于订阅**：xiao 直接使用你电脑上已有的 AI 工具及其订阅。
- 如果你在 cmd / VSCode / Cursor 里可以用 `codex` 命令，xiao 也可以直接用
- 如果你用 ccswitch 切换账号，xiao 会使用当前激活的账号
- 不需要在 xiao 里单独配置 API Key（除非工具本身要求）

### 2.2 Python 环境

需要 Python 3.11 或更高版本。

```bash
python --version   # 应显示 3.11+
```

### 2.3 安装 xiao

```bash
# 克隆仓库
git clone <repo-url> xiao
cd xiao

# 创建虚拟环境（推荐）
python -m venv .venv
.venv\Scripts\activate   # Windows
# 或
source .venv/bin/activate  # Mac/Linux

# 安装
pip install -e .
```

## 三、快速启动

### 3.1 初始化工作空间

在你的项目目录里运行：

```bash
checkpoint init
```

这会创建 `.agent-workspace/` 目录，xiao 用它存储任务、日志、验收结果。

### 3.2 启动 Web 工作台

```bash
checkpoint dashboard
```

浏览器自动打开 `http://127.0.0.1:8787`，这就是 xiao 的可视化界面。

### 3.3 派发第一个任务

在 Web 工作台的「新建任务」区域：

1. **目标**：用中文描述要做什么，越具体越好
   - 好：`修复 src/calc.py 的 divide 函数，当除数为 0 时抛出 ZeroDivisionError 而不是返回 None，让 pytest tests/test_calc.py 通过`
   - 差：`修复 bug`
2. **验收命令**：填 `pytest -q` 或 `npm test`（留空则自动探测）
3. **项目根目录**：留空则使用当前项目
4. **AI**：从下拉选择 codex / claude-code / gemini
5. 点 **▶ 执行**

## 四、Web 工作台功能详解

### 4.1 看板

- **待办**：已创建但尚未开始的任务
- **执行中**：AI 正在运行的任务
- **待验收**：AI 已完成修改，等你点「合并」
- **已完成**：验收通过且已合并的任务

点击任意任务卡片，右侧抽屉显示详情（执行轮次、改动文件、最终报告）。

### 4.2 切换项目

点击页头的项目路径或「切换项目」按钮，在弹窗中：
- 直接输入 `.agent-workspace` 目录的完整路径
- 或点击自动发现的已知工作空间

切换后，看板和统计数据立即更新为新项目的状态。

### 4.3 Worker（队列模式）

Worker 是批量处理队列的后台进程。

- 点「启动 Worker」→ 自动依次执行队列里的任务
- 状态指示灯：绿色 = 运行中，灰色 = 空闲

命令行排队：
```bash
checkpoint mission queue --goal "实现登录功能" --agent codex
checkpoint mission queue --goal "添加单元测试" --agent claude-code
```

### 4.4 重试失败任务

任务卡上出现「↺ 重试」按钮时，点击会用相同目标重新派发任务。

常见停止原因及解决方法：

| 原因 | 解决方法 |
|------|---------|
| 未找到测试命令 | 在「验收命令」框填写测试命令 |
| 仓库有未提交的改动 | 先 `git commit` 或 `git stash` |
| 同一错误重复失败 | 把目标描述得更具体 |
| AI 额度耗尽 | 等额度恢复，或切换到另一个 AI |

## 五、命令行使用

Web 工作台之外，xiao 也有完整的 CLI：

```bash
# 查看所有命令
checkpoint --help

# 运行单个任务（不走队列）
checkpoint run --goal "修复登录 bug" --agent codex

# 查看已安装的 AI 工具状态
checkpoint agents doctor

# 显示当前项目验收状态
checkpoint status

# 启动队列 worker
checkpoint mission worker --watch
```

## 六、多项目使用

每个项目独立初始化一个 `.agent-workspace/`。

```
D:\
├── 项目A\
│   ├── src\
│   └── .agent-workspace\     ← 项目A 的 xiao 数据
└── 项目B\
    ├── src\
    └── .agent-workspace\     ← 项目B 的 xiao 数据
```

同一个 xiao 实例可以通过 Web 工作台「切换项目」在不同项目间切换查看。

## 七、与各开发工具配合

### VSCode / Cursor
在 VSCode 终端里直接运行 `checkpoint dashboard`，工作台在浏览器中打开。xiao 不依赖 VSCode 扩展（扩展是可选的增强）。

### cmd / PowerShell
直接运行命令，无特殊配置。

### ccswitch 用户
ccswitch 管理 Claude Code 的账号切换。切换账号后，xiao 下次调用 claude-code 时会使用新账号，无需在 xiao 里做任何操作。

### Codex 官方 App
如果你通过 Codex 官方 App 安装了 codex CLI，xiao 会直接调用同一个可执行文件，共用同一个订阅额度。

## 八、常见问题

**Q: 下载 exe 就能用吗？**
A: 目前不能，xiao 需要 Python 环境和 AI 工具的 CLI。EXE 打包在计划中，但还没做。

**Q: xiao 会消耗我的 Codex / Claude 额度吗？**
A: 是的，xiao 调用 AI 工具执行任务时会消耗对应的额度。xiao 本身不计费，计费由你选择的 AI 工具决定。

**Q: 任务运行完了，代码在哪里？**
A: AI 在隔离的 git 分支里修改代码。验收通过后，点「合并」才会把改动合并到你的主分支。

**Q: 看不到任务历史怎么办？**
A: 确认工作台的项目路径显示的是正确的 `.agent-workspace`。如果不对，点「切换项目」选择正确路径。
