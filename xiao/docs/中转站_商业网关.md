# Pacer 商业中转站

Pacer Gateway 是现有 `cloud_api` 内的一套单机商业试点网关。它面向拥有合规 API 使用与转售权的 OpenAI-compatible 上游，不转卖个人订阅、不导入浏览器 Cookie，也不复用 Codex 登录凭证。

## 五分钟启动

安装 Cloud 依赖并生成管理员凭证：

```powershell
python -m pip install -e ".[cloud]"
python -m cloud_api.setup_gateway --env-file cloud_api/.env.gateway
```

第二条命令只把管理员 token 的哈希与盐写入环境文件，明文 token 仅在当前终端显示一次。随后把真实上游 key 填入 `cloud_api/.env.gateway`，变量名可以自定，例如 `PACER_UPSTREAM_OPENAI_KEY`。

启动：

```powershell
docker compose -f docker-compose.gateway.yml up -d --build
```

打开 `http://127.0.0.1:8000/gateway`，依次完成：

1. 创建套餐和客户。
2. 配置公开模型、售卖价格和保守的上游成本。
3. 新增 OpenAI-compatible 上游，`secret_env` 填环境变量名，不填密钥值。
4. 测试线路并签发客户 key。
5. 客户把 Base URL 设为 `http://127.0.0.1:8000/v1`，API key 使用 `pacer_sk_...`。

## 已落地闭环

- 多租户、套餐、客户 API key；客户 key 只保存 salted SHA-256，明文只返回一次。
- `/v1/models`、`/v1/chat/completions`、`/v1/responses`、`/v1/embeddings`。
- 多条同构 OpenAI-compatible 上游的优先级、权重、并发上限、熔断和首块前切换。
- 每分钟限流和并发限制同时按客户与 key 执行，不能靠多发 key 绕过套餐。
- 请求前余额预占，结束后按冻结价格快照结算；最终扣费不超过预留，不产生负余额。
- 流式终态校验、拆分 usage 合并、客户端断开后继续读取上游、长流心跳续租。
- 请求幂等键、请求指纹和逐次上游 attempt 记录；同键异载荷拒绝。
- 崩溃恢复区分“尚未发给上游”和“结果不确定”：前者自动释放，后者进入人工 capture/release 对账。
- 付费套餐只有在续费期间内才能鉴权和预留；外部支付号在所有客户、充值和续费流程中全局唯一。
- attempt 记录上游 request ID、token 和上游成本；模糊的 2xx 读取失败不会切换线路，而是保留预占等待人工对账。
- 请求日志不保存 prompt 或响应正文；上游明文 key 只从运行环境读取。
- 管理工作台包含客户、套餐续费、余额、key 生命周期、上游健康、价格、请求和资金账本。

客户端应为每个可重试的逻辑请求发送稳定的 `Idempotency-Key` 或 `X-Request-Id`。没有这两个头时，网关会为了 OpenAI 客户端兼容性生成请求 ID，但无法识别客户端侧的重复提交。

## 金额口径

后端所有金额使用整数 `micro-USD`：`1 USD = 1,000,000 micro-USD`。价格字段表示每一百万 tokens 的 micro-USD 值。工作台自动换算为 USD。

请求账本的 `reserve` 是预占，`settlement` 是预占与实际扣费的差额，`release` 是失败退款。`actual_microusd` 是已消耗余额，不是支付机构的现金到账额；工作台因此把“计费额”和来自充值、套餐确认的“已确认收款”分开显示。毛利是用量计费额减上游成本，不是现金流利润。

套餐续费接口要求管理员提供已经核实的外部交易号，并按套餐月费校验到账金额，再幂等发放包含额度。它适合人工转账、合同客户或小范围收费试点。

人工 `capture` 可填写最终客户扣费、上游成本和 token 数；少于预占的部分会自动退回客户余额。支付流水使用全局外部交易号，实际接入时建议带渠道前缀，例如 `bank:20260714:000123`。

## 当前商业边界

第一版还没有支付宝、微信或 Stripe 的签名 webhook、退款和主动对账任务。因此它已经能做人工收款后的幂等入账与用量计费，但不能宣称“自动支付闭环”。公开自助售卖前，需要再接一个持牌支付机构并增加订单状态机、签名回调、退款和日终对账。

第一版只接受同步、文本输入、token 计费的请求以及自定义 function tools。`background=true`、图像/音频/文件输入，以及 web search、file search、code interpreter、hosted shell、image generation、MCP 等上游另行计费的托管工具会在请求发往上游前拒绝。要开放这些能力，必须先增加任务终态轮询和对应的按次、存储或容器计价器。

多条上游必须使用相同的 OpenAI-compatible 协议、公共模型映射和成本合同，并填写相同的 `routing_contract`。同一公开模型存在多个候选但合同标识为空或不一致时，网关会停止该模型的路由。若实际供应商的模型别名或成本不同，应拆成不同公开模型；当前版本不做异构协议转换。

当前存储是 SQLite，适合单机和小流量试点。多节点部署前应把余额事务、租约、RPM 和并发状态迁移到 PostgreSQL/Redis，不能让多个容器各用一份本地数据库。

所有远程部署都应在反向代理后启用 HTTPS，限制 `/api/gateway/admin/*` 的网络来源，并备份 `/data/gateway.db`、WAL 和审计日志。不要把 `.env.gateway`、上游 key、客户 key 或数据库提交到 Git。
