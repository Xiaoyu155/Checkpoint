**定位因此收窄为一句话：**

> 别人做「让会写代码的人管好 agent」，Pacer 做「让不会写代码的人也敢用 agent」。

前一句有 12 万星的对手，后一句没人做——不是做不到，是他们的用户本来就会读 diff。

### 2.1 交付关卡（`41088c7`）—— 全网只有 Pacer 有

**驱动事故**：8-04 一个 mission 验收通过，测试 22/22 全绿，功能却无法从干净检出启动——它 import 了只存在于未提交改动里的符号。Pacer 说做完了，用户什么也拿不到。

**做法**：验收通过后带 mission id 提交 → `git worktree add --detach` 干净检出 → 在那里重跑真实验收命令。

三档判定：`delivered` / `not_delivered` / **`unchecked`**（验不了就说验不了，绝不往两边猜）。依赖目录用 junction 链入（环境不算源码，缺了判 unchecked 不判失败）。`not_delivered` 挡自动合并；用户故事不再说「可以收工了」。

**关键教训**：静态分析替代不了这件事。第一版检查"import 的文件是否已提交"，报告全绿，交付验证照样挂——文件提交了，**文件里的那个导出没有**。

**实测**：真实事故上 0.4 秒验出，三个提交里两个 delivered、生日贺卡 not_delivered。

### 2.2 完工证据（`eff462d`）

把「exit 0」换成人能判断的行为清单——从 TAP / pytest -v / go test / jest 输出里挖出每条被检查的行为名。测试名本来就是人话：

```
ok 8 - a birthday card never carries medical advice
```

刻意的克制：每份报告都写明「**不能说明**界面好不好看、文案合不合适、这功能是不是你真正想要的」。输出里挖不出行为名时，直接说"你只能选择信或不信，这不太好"，而不是拿个 exit code 糊弄。

### 2.3 三个"说谎"缺陷（`23d0dfa` / `6a23eb4` / `b9aef81`）

这三个都是同一类问题：**系统给出的结论与真相不符，且会把人引向无用功。**

| 缺陷 | 症状 | 修法 |
|---|---|---|
| 真因被预算盖掉 | worker 改了测试被拒，报「时间和次数用满了」，下一步给「加大轮数重试」——照做永远失败 | 拒绝类失败在所有预算分支之前判定；拒绝类不给任何重试建议 |
| 门坏了当成门红了 | 一道有语法错的门从未执行，却被当成"契约先行"派了工，烧掉整轮 | base 探测判红前先看它执行没执行（SyntaxError / 模块找不到 / 零用例 → `gate_broken`） |
| 托管时长是谎 | 申请 5 小时跑 45 分钟，3 件没做成的事被丢下，剩余 4 小时没用 | 收工前先重试"重试有意义"的失败；结果如实印出「实际 45 分钟（申请 300 分钟）」 |

第三条有一句必须说清的诚实：**这个修复让预算用得更充分，但仍不保证跑满。** 真要跑满需要它能自己找活干，风险高得多，应另行设计。

### 2.4 甲方角色（`1eceb07` / `7e7f3c0`）

原本三道门（防篡改、防越界、验收链保护）**全是防作弊，不防跑偏**。P0-P4 补的是这个：

- **P0** 修复轮无条件重锚目标——resume 时目标曾被主动丢弃，每轮只追上一个错误，是结构性漂移源
- **P1** worker 反驳通道（规格矛盾 / 做不到 / 有更好做法）
- **P2** 改动面声明与对账
- **P3** 主张—证据台账（本地源码 > 探针 > 上游，上游必须钉 commit/tag）
- **P4** 差异评审（只读 diff，带 base 对照，**绝不自动拦截**）

## 三、实测数据（这一阶段最有价值的部分）

### 3.1 派工粒度决定成败

托管实测 10 个目标：

| 目标类型 | 结果 |
|---|---|
| 「改某个具体文件」 | **7/7 verified** |
| 「扫描 src 下所有 .vue 文件」 | **0/3**，全部 `same_failure_repeated` |

**规律干净得可以直接写进产品规则。**

### 3.2 `PACER-REPORT` 交回率：0 / 17

17 次完成的 worker 尝试，claude-code **零交回**。P1/P2/P3 依赖 worker 填表这条路，在真实运行里没有采纳。

**处置**：P2 改从**目标文本**推断改动面（目标里点名的文件就是声明），从死代码变成默认生效；P1 与 P3 推不出来，保留但不假装生效——报告始终写着"没有交回，所以「它没意见」这句话没有证据"。

**未决**：这是模型习惯还是设计问题，**需要换 codex 再测一轮才能判**。

### 3.3 写门的人自己要守的纪律

两条都是这一阶段用真金白银换的：

1. **门写完必须做判别性验证** —— 故意塞回违规看它红，还原看它绿。一道无论如何都红（或都绿）的门，等于没有门。本阶段所有新增的门都做了这个验证。
2. **门要按目标切分** —— 空态契约写成"全有或全无"，导致每个"只改一个页面"的目标都被迫做整份工作，8 个 worktree 各装一份完整解，**7 倍重复烧额度**。
