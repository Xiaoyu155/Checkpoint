```
xiao/
├── src/visual_agent/           # 核心 Python 包
```

## 2. 核心模块说明

### `dashboard.py`

Web 工作台，使用 Python stdlib `http.server`，无外部依赖。

关键函数：
- `serve_dashboard(workspace_root, host, port)` — 启动 HTTP 服务
- `build_dashboard_data(workspace_root)` — 构建 `/api/data` 的 JSON 响应
- `build_mission_detail(workspace_root, mission_id)` — 构建任务详情抽屉数据
- `start_workbench_mission(...)` — 从 Web 表单派发任务
- `_run_chat(payload)` — 多轮对话后端（调用 AI CLI）
- `_set_active_workspace(path)` — 工作空间切换（接受项目根目录或 .agent-workspace 路径）
- `_list_known_workspaces()` — 扫描已知工作空间列表

HTML/JS 嵌入在 `DASHBOARD_HTML` 字符串常量中（约 1200 行）。

### `chief_run.py`

Mission 执行主循环。`run_chief_mission(goal, workspace_root, ...)` 是核心入口：

1. 调用 `chief_dispatch.py` 拿到执行计划（plan）
2. 为每个 worker track 调用对应 AI（via `agent_backends.py`）
3. 在隔离 git worktree 里执行
4. 跑验收命令（`verification_profiles.py` 决定用什么命令）
5. 写结果到 `missions/` 目录

### `agent_backends.py`

AI 工具适配层。每种 AI 有一个后端函数：

- `run_codex_backend(goal, ...)` — 调用 `codex` CLI
- `run_claude_code_backend(goal, ...)` — 调用 `claude` CLI
- `run_mimo_backend(goal, ...)` — 路由到 claude-code（MiMo 别名）
- `resolve_backend_by_name(agent)` — 按名字找后端函数

### `agent_capabilities.py`

AI 工具安装检测：

- `agents_doctor()` — 检测所有已知 AI 工具，返回安装状态和版本
- `probe_agent(profile)` — 用 `shutil.which` 检测单个 AI 的可执行文件
- `load_agent_profile(agent)` — 读取 `agent_profiles/*.yaml` 能力档案

Windows 注意：npm 全局 CLI（codex/claude）以 `.cmd` 形式安装，`probe_agent` 通过检测 `.cmd` 后缀并路由到 `cmd /c` 来处理。

### `workflow.py`

工作流 YAML action 执行引擎。当前支持的 action 类型见 `validation.py` 的 `SUPPORTED_ACTIONS`：

- `open_url`、`navigate`、`click`、`type`、`screenshot` — UI 自动化
- `run_command` — 执行 shell 命令（2026-07 新增）
- `assert_*` — 各类断言

### `acceptance.py`

验收逻辑，三个验收级别：

- **L1 Basic**：验收命令返回 0（测试通过）
- **L2 Interaction**：有真实的 UI 或命令行交互操作
- **L3 Data Round Trip**：交互后有可观察的数据变化断言

## 3. 数据流：从目标到验收

```
用户输入目标
    ↓
chief_run.run_chief_mission()
    ├── chief_dispatch: 生成 plan（任务分解、分配 worker）
    ├── agent_backends: 调用 AI CLI 在 git worktree 里改代码
    ├── verification_profiles: 探测验收命令（pytest/npm test 等）
    ├── 执行验收命令
    └── 写 mission 结果到 .agent-workspace/missions/<id>/
        ├── mission.json       (状态、目标、agent、stop_reason)
        ├── rounds.jsonl       (每轮执行记录)
        └── final_report.md   (最终报告)

dashboard.build_dashboard_data()
    ├── missions.list_missions()              → 读取所有 mission.json
    ├── workbench_board.attach_board_fields() → 计算 board_column
    ├── chief_plans_store.list_plans()        → 读取执行计划
    ├── agent_capabilities.agents_doctor()    → 检测 AI 工具
    └── mimo_efficiency.compute_mimo_efficiency() → 效率指标
```

## 4. 如何添加新 AI Agent 支持

**Step 1：创建 agent_profiles YAML**

在 `src/visual_agent/agent_profiles/` 新建 `<agent-name>.yaml`，参考 `codex.yaml` 格式：

```yaml
agent: my-agent
display_name: My Agent
executable: my-agent          # shutil.which 会搜索这个命令
version_command: my-agent --version
primary_role: coding
headless:
  command: my-agent --no-sandbox
models:
  - id: my-model
    role: default
```

**Step 2：注册别名**（可选）

在 `agent_capabilities.py` 的 `AGENT_ALIASES` 字典中添加：

```python
AGENT_ALIASES = {
    ...
    "myagent": "my-agent",
    "my-agent": "my-agent",
}
```

**Step 3：实现后端函数**

在 `agent_backends.py` 中添加 `run_myagent_backend(goal, ...)` 函数，参考 `run_codex_backend`。

**Step 4：注册到 resolve_backend_by_name**

在 `resolve_backend_by_name(agent)` 中添加分支。

**Step 5：在对话功能里注册可执行文件名**

在 `dashboard.py` 的 `_run_chat()` 函数的 `exe_map` 字典中添加映射。

## 5. 如何添加新 Workflow Action

**Step 1：在 `validation.py` 注册**

```python
SUPPORTED_ACTIONS = {
    ...,
    "my_action",          # 添加到支持列表
}
REQUIRED_PARAMS = {
    "my_action": ["param1"],     # 必填参数
}
```

**Step 2：在 `workflow.py` 实现**

在 `execute_action(action, ...)` 中添加处理分支：

```python
elif action_type == "my_action":
    param1 = str(action.get("param1") or "")
    # ... 执行逻辑
    return {
        "ok": True,
        "operation_receipt": {
            "action": "my_action",
            "result": "...",
        }
    }
```

**Step 3：在 `acceptance.py` 处理验收**

如果 action 有 UI 交互，加入 `INTERACTION_ACTIONS`；如果不需要 UI 断言（如 `run_command`），在 `validate_operation_receipt` 中做专门处理。

## 6. Dashboard 开发

Dashboard 是单文件 Python HTTP 服务，HTML/CSS/JS 全部内联在 `DASHBOARD_HTML` 字符串里。

### 本地开发

```bash
# 启动 dashboard
checkpoint dashboard --workspace-root .agent-workspace

# 修改 dashboard.py 后，重启 checkpoint dashboard 即可生效
```

### API 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/data` | 主数据（missions、queue、agent 状态等） |
| GET | `/api/mission?id=<id>` | 单任务详情 |
| GET | `/api/workspaces` | 已知工作空间列表 |
| POST | `/api/mission/start` | 派发新任务 |
| POST | `/api/mission/merge` | 合并任务到主分支 |
| POST | `/api/mission/retry` | 用相同目标重试失败任务 |
| POST | `/api/worker/start` | 启动队列 Worker |
| POST | `/api/worker/stop` | 停止 Worker |
| POST | `/api/workspace/switch` | 切换工作空间（接受项目根目录或 .agent-workspace 路径） |
| POST | `/api/chat` | 多轮对话（调用 AI CLI） |

### 前端轮询频率

前端每 4 秒调用一次 `/api/data`（`setInterval(load, 4000)`）。

## 8. 构建与发布

### 打包为 exe（Windows）

```powershell
# 需要 PyInstaller
pip install pyinstaller

cd xiao/
powershell -ExecutionPolicy Bypass -File scripts/build_exe.ps1
```

产物在 `xiao/dist/Pacer/Pacer.exe`（约 15MB + 依赖文件夹）。

### 发布 Python 包

```bash
cd xiao/
pip install build
python -m build
```

### VSCode 扩展打包

```bash
cd xiao/vscode-extension/
npm install
npm run compile
npx vsce package
```

## 9. 贡献指南

### 代码风格

- Python：遵循 PEP 8，使用 Ruff 格式化（`ruff check . --fix`）
- 函数命名：小写下划线
- 不添加无意义注释；只注释"为什么"而非"是什么"

### Commit 规范

```
类型: 简短描述（50 字符以内）
```

类型：`feat` / `fix` / `refactor` / `test` / `docs` / `chore`

### 新功能提交前

1. 写测试（或说明为何不需要）
2. `python -m pytest xiao/tests/ -x -q` 通过
3. `checkpoint agents doctor` 确认工具链正常
4. 更新 `docs/开发文档.md` 中相关章节
