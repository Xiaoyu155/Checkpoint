## 五核心功能核实

### 1. Routing

判定：部分通过。

最近 6 个 journey 里：

```text

routing blocked: 1
```

成功证据：

```text
20260729-001908-979829-e9f9c8-259d532c
routing: claude-code · claude-code / haiku
```

worker 记录显示：

```text
agent = claude-code
resolved_model = haiku
routing_evidence.verdict = matched
routing_evidence.policy_match = true
decision.required_tier = cheap
decision.model = haiku
request.provider = claude-code
request.model = haiku
```

问题证据：

```text
20260729-000221-324500-c8db18-ac317278
routing: blocked
reason = routing_identity_missing
summary = claude-code · 待定 / opus
```

意见：

Routing 已经能在成功路径里完成“任务层级 → agent/model → 实际 worker”的绑定，但不是全稳定。至少有一次记录显示路由身份缺失，说明 journey 和 dispatch 的身份证据仍可能断。

## 和模型的关系

这次核实支持用户判断：主要问题不是模型。

模型相关证据只说明路由能选择 `claude-code / haiku` 或 `claude-code / sonnet`，且成功任务能完成。失败更多来自：

1. quota / budget 阻塞。
2. routing identity 缺失。
3. worker permission denial。
4. 托管恢复和状态聚合不足。
5. 最新记录分散，用户看不到连续开发线。

所以继续只换更贵模型，不能解决 Pacer 的核心问题。

## 下一步应该修什么

优先级最高的不是模型选择，而是：

```powershell
pacer usage timeline --days 14
```

这个命令应跨 workspace 汇总：

- mission
- journey
- run_history
- gui/actions
- background
- host/session
- worker logs
- verification evidence

其次：

1. 修空消息 / resume event 过滤。
2. 修 journey 路由身份缺失。
3. 把 memory load 压缩成用户可读摘要。
4. 把 managed failure 归因做到可恢复，而不是只写 stopped。
5. 让 final report 自动引用最新 evidence，不要求用户翻 `.agent-workspace`。
