## 一句话定位

这个产品由三层组成：

- **Pacer / DevPacer**：面向用户的 AI 编码任务调度器，用自然语言创建任务，调度 Codex / Claude Code / Gemini 等本地 CLI，在隔离分支或工作树里执行，并把通过验收的结果交给用户合并。
- **Checkpoint**：底层验证与可视化自动化引擎，负责运行 YAML/JSON 工作流，观察页面/桌面状态，解析目标，执行动作，生成审计记录、失败诊断和验收报告。
- **visual-agent Python 包**：实际实现包名，提供 CLI、SDK、MCP Server、Dashboard、工作台、Cloud API 适配和测试基础设施。

安装入口来自 `xiao/pyproject.toml`：

- Python 包名：`visual-agent`
- 版本：`0.1.2`
- CLI 命令：`checkpoint`、`pacer`、`visual-agent`
- MCP 命令：`visual-agent-mcp`
- 主入口：`visual_agent.cli:main`

## 总体运行链路

核心验证链路可以概括为：

```text
用户/AI Agent
  -> checkpoint / pacer CLI 或 Web Dashboard / VS Code 扩展 / MCP
  -> 工作空间 .agent-workspace
  -> DevPacer mission / Checkpoint workflow
  -> Provider 观察系统状态
  -> Selector 解析目标
  -> Dispatcher 执行动作或 dry-run
  -> Audit / State / Report 写入 .runs
  -> Acceptance / Product Guard / Visual Guard 判定结果
  -> 通过则待验收或合并，失败则生成诊断、修复建议、可重跑状态
```

官方文档里定义的自动化内核是：

```text
Observation -> Target -> Selector -> Action -> Workflow -> Audit -> Report
```

这条链路对应的核心实现主要在：

- `models.py`
- `providers.py`
- `selector.py`
- `dispatcher.py`
- `actions.py`
- `workflow.py`
- `audit.py`
- `reports.py`
- `acceptance.py`
- `visual_rules.py`
- `product_state.py`

## 核心数据模型

文件：`xiao/src/visual_agent/models.py`

这里定义了整个验证引擎的基础对象：

- `ProviderKind`：观察来源，包含 `screen`、`dom`、`uia`、`ocr`、`vision`、`mock`。
- `ActionStatus`：动作状态，包含 `success`、`dry_run`、`failed`。
- `Point` / `Bounds`：屏幕坐标和矩形区域。
- `Target`：用户或工作流想操作的目标，支持 text、role、label、selector、test_id、行/列文本、near/scope 等语义字段。
- `Observation`：一次观察结果，可能来自 DOM、UIA、OCR、屏幕截图、VLM 等。
- `LocationEvidence`：目标定位证据，包含 provider、confidence、reason、point/bounds/handle。
- `ResolvedTarget`：目标和定位证据的组合。
- `ActionResult`：点击、输入、粘贴等动作的审计结果。
- `to_jsonable`：把 dataclass、Path、Enum 等转换为可落盘 JSON。

这些类型贯穿 Workflow、MCP、报告、Dashboard 和测试。

## Checkpoint 工作流引擎

主文件：`xiao/src/visual_agent/workflow.py`

职责：

- 解析 YAML/JSON 工作流。
- 管理 `Workflow`、`WorkflowStep`、`WorkflowRunResult`。
- 执行 preconditions、fixtures、steps。
- 支持 dry-run、supervised、approved 等运行 profile。
- 通过 `RunLock` 防止多个工作流同时抢桌面/浏览器资源。
- 支持 resume/from-step、状态持久化、输入变量、敏感字段脱敏。
- 调用 ProviderRegistry 获取观察结果。
- 调用 SelectorResolver 定位目标。
- 调用 ActionDispatcher 执行动作。
- 每步写审计 JSON，每次运行写 `workflow_result.json` 和 report。
- 集成 Product Guard、Visual Guard、Acceptance Grade、Failure Diagnosis。

## Selector 和 Action 层

主文件：

- `selector.py`
- `dispatcher.py`
- `actions.py`

`selector.py` 的职责是把 `Target` 转成 `LocationEvidence`。DOM 策略支持：

- exact selector / test id
- text / label / role
- contains text / regex
- table row / column header
- near text
- dialog/scope 约束

`dispatcher.py` 负责把工作流 action 分发到合适执行路径，例如：

- Playwright DOM-native click/fill
- 坐标点击
- 输入/粘贴
- assert_text / assert_response / assert_file_exists
- 下载、截图、storage_state、等待、变量读取等工作流动作

`actions.py` 封装桌面动作，底层主要面向 `pyautogui`，并处理鼠标/修饰键释放、剪贴板粘贴等安全细节。

## 安全和边界控制

产品里有多层安全控制：

- 工作流默认 dry-run。
- 真实点击需要 supervised/approved profile 或兼容参数。
- 高风险 planner 能力默认 blocked，需要显式允许。
- MCP 限制 workspace 路径、artifact 路径和响应长度。
- 输入、凭证、storage_state、API key、敏感字段会脱敏或只保存 hash。
- `RunLock` 避免多个工作流同时操作桌面/浏览器。
- `preflight` 在执行前检查 provider/action 依赖和风险。
- `workspace_risk_policy.py` 支持 workspace 级风险策略。
- `security.py` 负责 secret scrub/redaction。
- `licensing.py` 和 `telemetry.py` 提供许可和遥测边界，遥测默认关闭。

- 登录、注册、找回密码、退出登录。
- 表单填写、多步表单、搜索、过滤、inline edit。
- 电商：商品列表、商品详情、加购、结账、订单确认。
- 后台管理：仪表盘、表格、新建、编辑、删除确认。
- 浏览器能力：网络断言、下载断言、storage_state 保存/恢复、表格行列选择。
- 桌面视觉：Notepad、screen click、OCR、vision mock。
- Demo App：Vue/Vite、Next.js。
- 外部样例：客服工单、库存补货、财务对账、电商订单。

模板在 `templates/`：

- `login_form`
- `order_entry`

- `desktop_ocr_real_acceptance`

## local-sub2api

路径：`local-sub2api/`

这是一个独立的小工具，不属于 Pacer/Checkpoint 主源码。作用是把多个正规 OpenAI 兼容 API 统一成本地入口：

- 默认监听 `127.0.0.1:8787`
- 配置文件：`config.json`
- 示例配置：`config.example.json`
- 启动脚本：`start.ps1`
- 主程序：`sub2api_local.py`

它不把网页订阅绕成 API，只做本机 OpenAI 兼容转发。

## 需要注意的仓库现状

当前根目录 git 状态显示大量旧路径删除，同时新增 `xiao/`，说明主产品源码已经被整体移动/整理到 `xiao/` 子目录。阅读和开发时建议以 `xiao/` 为准。

- `xiao.checkpoint-worktrees/`：自动/并行任务产生的 checkpoint worktree 副本。

根目录 `README.md` 当前内容看起来不是 Pacer/Checkpoint 产品 README，而是关于 Claude Code clean-room/source-map 的说明；产品文档应优先看 `xiao/docs/`。

## 维护判断

这个产品不是单一脚本，而是一个“本地 AI 编码任务调度器 + 可视化验收引擎 + IDE/MCP/Cloud 集成”的组合项目。源码重心在 `visual_agent` 包内：

- `workflow.py` 是 Checkpoint 验证引擎的核心。
- `chief_run.py` / `chief_dispatch.py` / `chief_engineer.py` 是 DevPacer 任务调度核心。
- `cli.py` 是所有功能的统一入口。
- `mcp_server.py` 是给其他 AI 工具调用的集成入口。
- `dashboard` / `workbench` 是用户可视化操作入口。

后续开发建议保持这几个边界清晰：

- Checkpoint 只负责可验证、可审计的自动化执行。
- DevPacer 负责 AI 编码任务计划、调度、验证、重试和合并。
- Dashboard/VS Code/MCP/Cloud 只是入口和适配层，不应复制核心逻辑。
- 真实点击、凭证、下载、外部账号、Cloud 发布等能力必须继续走 preflight、run profile、脱敏和审计。
