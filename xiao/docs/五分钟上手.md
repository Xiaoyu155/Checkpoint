# DevPacer 五分钟上手

DevPacer 帮你托管 AI 编码任务：你给目标，它派 AI worker 在隔离分支里干活，用你的测试命令验收，通过了才让你合并。**它不打包票，它让失败可见。**

以下每条命令都在 2026-07-04 的验证中真实跑通过（见 `docs/验证记录.md`）。

## 0. 前提（1 分钟）

- Windows / Python 3.11+
- 装好至少一个 AI worker CLI：`codex`（OpenAI Codex CLI）或 `claude`（Claude Code）
- 你的项目是一个 git 仓库（没有也行，`git init` 一下）

## 1. 安装（1 分钟）

```powershell
cd DevPacer仓库目录
python -m pip install -e .
```

验证装好了：

```powershell
checkpoint quickstart        # 输出欢迎信息
checkpoint agents doctor     # 确认识别到 codex / claude
```

## 2. 跑通内置演示（1 分钟）

```powershell
checkpoint chief-run-demo
```

看到 `status: verified` 就说明整条"计划→开发→验收"链路在你机器上是通的。这一步不消耗任何 AI 额度。

## 3. 给你的项目派第一个真实任务（2 分钟）

进入你的项目目录，一条命令：

```powershell
pacer
```

进入 Pacer Agent 后持续下达任务：

```text
Pacer> 给 utils 加一个 slugify 函数并写测试
Pacer> /provider subscription
Pacer> /provider relay custom
Pacer> 继续补边界测试
Pacer> /状态
Pacer> /退出
```

要点：

- 自然语言里写清楚目标和完成标准，Pacer 自动调用 Codex、注入本地记忆并运行验收
- 验收通过且主分支干净时自动合并；失败或主分支有未提交改动时不会覆盖你的代码
- 第一次运行自动创建 `.agent-workspace/`，不需要先初始化或填写 provider、model、worker 参数
- `checkpoint mission start ...` 等完整参数仍保留给需要精确控制的高级场景
- 底层只调用用户已安装的 Codex CLI：沿用用户订阅，或沿用 Codex 配置的中转 provider；不会自动切到 MiMo
- `/provider subscription` 使用 Codex 登录订阅；`/provider relay <id>` 使用 Codex `config.toml` 中已配置的中转 provider；`/provider inherit` 恢复沿用当前配置。Pacer 不读取或保存中转 key

结束后你会看到：改动摘要（几个文件、+/-多少行、动了哪些函数）、门禁输出、和一份"你需要手动确认什么"的清单。

## 4. 想托管一批任务？用看板（可选）

把任务写成 markdown checklist（`开发计划.md`）：

```markdown
- [ ] 创建 utils/slugify.py 并写测试，要求 ...
- [ ] 给 API 加分页参数并写测试，要求 ...
```

然后：

```powershell
checkpoint autopilot --file 开发计划.md --agent codex --test-command "python -m pytest -q" `
  --workspace-root .agent-workspace --repo-root .
checkpoint chief-worker --workspace-root .agent-workspace --watch --max-items 10
```

worker 会按顺序执行：每个任务 verified 后自动放行下一个。打开看板实时看进度、点卡片看审查详情、一键合并：

```powershell
checkpoint dashboard
```

## 5. 常见问题

- **Codex 通道额度用完了？** 闭环 Program 可配置备用 Codex provider，在订阅通道与 OpenAI/Codex-compatible 中转 token 通道之间接管；执行引擎仍是 Codex。没有配置备用 provider 时会如实报告 `quota_exhausted`，不会静默换成能力不同的 worker。
- **任务失败了？** 主分支不会被污染。看 mission 的最终报告（`checkpoint mission status --mission <id>`），失败原因和修复建议都在里面。
- **AI 会不会改我的测试来蒙混过关？** 不会。测试文件是验收契约，worker 改动测试会被守卫拒绝——除非你的目标明确要求"写测试/加测试"。
